Inside the boundary

Two exception rules, priority queue, ownership and escalation, evidence and cost on every decision, audit log, data-freshness guard, outcome measurement against the Round 1 pilot targets, English and Vietnamese UI.

Outside, read only

Order and warehouse systems keep owning orders, stock and dispatch. PromiseOps never writes back; if it is down, staff use the current floor process. API calls need an X-API-Key when one is configured.

Deliberately not in the MVP

  • Write-back, routing, replenishment, promise changes
  • Customer messaging: "handed to customer service" is recorded, not sent
  • AI inside the product: rules first, as argued in Round 1
  • Company SSO: the demo uses a role switch

2 · CHECKDuplicates ignored, bad records rejected. No read after a milestone, or a feed older than 30 min: alerts pause, a data task opens.
3 · DETECTTwo rules raise one exception per order and cause, owned by the coordinator, 15-min timer, then escalation.
